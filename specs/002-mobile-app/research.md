# Research: Trap Pest Counter (phone app)

**Feature**: [spec.md](spec.md) | **Plan**: [plan.md](plan.md) | **Date**: 2026-10-19

Decisions behind the plan, written after the app was built from what the code, tests, README and decision log show. Facts about the models (thresholds, review levels, sizes, accuracies) come from the model pipeline, [001-model-training](../001-model-training/spec.md), and `docs/evaluation-record.md`.

## R1. Framework: Flutter or native Kotlin

**Decision**: Flutter (Dart) for Android.

**Rationale**:

- Most of the app is logic, not platform code: the contract, counting, manifests, registry, download and history. In Dart it runs under `flutter test` on any computer, so it was built test-first without a phone (140 host tests today).
- One codebase can later gain other targets; the desktop app ([003-desktop-app](../003-desktop-app/spec.md)) reuses it unchanged.
- An ONNX Runtime binding exists for it (`flutter_onnxruntime` 1.9.0, ONNX Runtime 1.28.0 on Android).
- Localisation is built in (`gen-l10n` with ARB files), and the ARB files are plain JSON that a test can scan for banned words.

**Alternatives considered**:

| Option | For | Against |
| :-- | :-- | :-- |
| Native Kotlin with ONNX Runtime's Android package | Smallest runtime overhead; first-class Android APIs | Android only; logic tests need an Android test setup; a second language for workshop participants to read |
| React Native | Familiar web stack | Needs a native module for ONNX Runtime and for byte-exact resizing; logic and UI split across JavaScript and native code |
| Convert the model to another on-device format | Possibly smaller and faster | A second exported artefact to keep in parity with the PyTorch model; the project's export and parity checks are for ONNX |

## R2. Where the model runs: on the phone or on a server

**Decision**: On the phone, with ONNX Runtime. No server.

**Rationale**: Photos stay on the phone (Principle V); the app works without a connection once a model is installed; there is no service to run, secure or pay for. The cost is a large download (122–172 MB per model) and an unmeasured phone latency (release gate 6, open).

**Alternatives considered**: A server that counts uploaded photos (rejected: photos would leave the phone, and a hosted service implies an operator and an endorsement the project does not give).

## R3. Image resizing: port Pillow's bilinear resampler byte for byte

**Decision**: A Dart port of Pillow 12.3's 8-bit bilinear resampler (fixed point, 22 precision bits, horizontal pass first) in `app/lib/inference/preprocess.dart`, checked against golden fixtures generated by the Python reference.

**Rationale**: The model was trained and evaluated on images resized by Pillow. Android's bitmap scaling and generic resize functions do not match it, and a different resize changes what the model sees. Golden fixtures make "matches the reference" a test instead of a hope: `tools/export_app_fixtures.py` writes 8 orientation cases, 8 resize shapes at 640 (up to 4032×3024) and 3 post-processing cases; `app/tool/export_resize_fixtures.py` adds 7 shapes at 576 for RF-DETR-M. No photos are stored: the test images are a deterministic pattern, `(x*7 + y*13 + c*101 + (x*y) % 31) % 256`, rebuilt in Dart. Pillow is pinned to 12.3.0 because 13.0 resizes some shapes differently (`docs/decisions.md`), and CI runs both generators with `--check`.

Pillow orders its two passes differently for inputs under about 10 px wide, so the app rejects photos under 32 px a side (`minSide`, `PhotoTooSmall`); no camera produces such images.

**Alternatives considered**: Letterboxing or a platform resize with a tolerance (rejected: the contract says no letterbox, and a tolerance would hide drift); resizing at pick time with `image_picker`'s `maxWidth` (rejected: it recompresses the photo, so the app passes no size or quality options).

## R4. Decoding and orientation

**Decision**: Decode with the `image` package (`app/lib/inference/decode.dart`), which applies the EXIF orientation to JPEGs itself; for other formats the app applies the tag with its own port of Pillow's `exif_transpose`. Grey and RGBA become RGB.

**Rationale**: `decode_test.dart` checks that the decoded JPEG is upright and matches Pillow for all 8 tags. JPEG decoders differ by a level or two per pixel (IDCT and colour conversion), so parity on real photos is detection-level, not byte-level. This difference is recorded in the code and the README.

**Open**: The difference has not been measured on real validation photos on a phone (task T037). The desktop app plans the same measurement and a libjpeg-turbo fallback if it shows a count difference ([003-desktop-app research R2](../003-desktop-app/research.md)).

## R5. Count history: one JSON file, not SQLite

**Decision**: `history/history.json`, a list of entries, written through a `.tmp` file and a rename (`app/lib/storage/history.dart`).

**Rationale**: One user's history is tens to hundreds of entries. JSON needs no native plugin and is tested on the host. A corrupt file is renamed to `.corrupt` and a fresh history starts, so the app always opens. Recorded in `docs/decisions.md` (2026-10-16), which notes that the first brief said SQLite.

**Alternatives considered**: SQLite (rejected: a native plugin, a schema and migrations for a list that fits in memory).

## R6. Strict model manifests

**Decision**: One JSON manifest per model, parsed strictly (`app/lib/model/model_manifest.dart`): 14 required fields and one optional (`notes`); unknown or missing fields, wrong types and out-of-range values are rejected. See [contracts/model-files.md](contracts/model-files.md).

**Rationale**: An imported model is enabled only when everything about it checks out (Principle VI). Range rules catch silent errors: `input_size` 320–1280; `threshold` and `review_below` strictly between 0 and 1; `threshold` above the detector floor (0.02), or counts would silently lose detections; `review_below` not under `threshold`; `outputs` fixed to `["logits", "pred_boxes"]`; `num_classes` 4. The bundled catalogue embeds the same manifests, and a test keeps them equal to `models/*.manifest.json`.

**Alternatives considered**: A lenient parser with defaults (rejected: a missing threshold would quietly fall back to 0.50 and change counts).

## R7. Model download: in the app, verified by size and SHA-256

**Decision**: Download only when the user taps Download, only from a URL in the bundled pin or catalogue. The file streams to a `.part` file with progress and cancel; more bytes than expected stop it; size and SHA-256 are checked; a catalogue download also goes through the ONNX session check before it is moved into `models/<id>/`. On any failure the partial files are deleted and the model in use is kept. A downloaded model is not made active automatically.

**Rationale**: Weights are too large for the repository and the APK (`docs/decisions.md`, 2026-10-18), and a pinned SHA-256 makes the download as trustworthy as a bundled file. Writes pause the stream while each chunk is written, so a fast connection cannot fill memory.

**Alternatives considered**: Bundling the model in the APK (rejected: 122–172 MB per model, and switching would need a new APK); letting the user type a URL (rejected: Principle V allows only bundled addresses).

## R8. No bundled model

**Decision**: The APK contains no model. A fresh install starts with no model and offers the download.

**Rationale**: Until 2026-10-16 the app bundled a 9.9 KB constant-output test model so it could run without real weights. It was removed so that no install can show counts that do not come from a real model (README, "Model modes"). The assets are only `model_pin.json` and `model_catalog.json` (`app/pubspec.yaml`). The cost: no automated test runs ONNX Runtime on a device any more; the on-device smoke test covers the no-model start only.

## R9. The default model is identified by SHA-256

**Decision**: `defaultModelSha256` in `app/lib/model/model_registry.dart` is r50-v5's file hash. `isDefault`, the banner and the "cannot delete" rule all use it.

**Rationale**: A manifest could claim the id `r50-v5` to escape the "Demo model, not validated" banner; a file hash cannot be claimed.

## R10. Service interfaces and fakes

**Decision**: Screens use only `AppServices` (`app/lib/app/services.dart`): `PhotoSource`, `Sharer`, `History`, `ModelCatalog`, `ModelFilePicker` and a `Detector`. ONNX Runtime sits behind `Detector` and `ModelProbe`. Tests supply fakes (`FakeDetector`, a recording sharer, in-memory history, fake probes and HTTP clients).

**Rationale**: Every screen, every import failure and every download failure is tested on the host in seconds. The same seams let the desktop app swap in its own photo source and sharer.

## R11. Compare: one model at a time

**Decision**: The compare screen loads, runs and frees each installed model in turn, reusing the active model's already-loaded detector instead of loading a second copy. Nothing is saved to history, and the photo copy is deleted when the screen closes or the next comparison starts.

**Rationale**: Three models of 122–172 MB each in memory at once is a risk on a low-end phone.

## R12. Species only, per-model thresholds, a detector floor

**Decision**: The app reports species (rice black bug, white stemborer), not sexes. Counting uses each model's `threshold` (inclusive) and flags a photo when a counted detection is below `review_below` or more than 30 are counted. The detector drops scores below 0.02 before counting; manifests must set thresholds above it.

**Rationale**: The project decided early to report species only; r50-v5 now passes the sex-class gate, but the app keeps species only, as designed (README, "Status and release gates"). `review_below` is the raw score whose calibrated probability is about 0.74 on validation photos (0.64, 0.63 and 0.68 for the three models). The crowded flag is fixed because crowded trays have the largest errors (white stemborer error 4.87 per photo on trays with 30 or more insects, r50-v5 on test).

## R13. Language

**Decision**: English and Filipino ARB files with the same keys. The app follows the phone's language; there is no in-app language setting.

**Rationale**: The workshop uses both languages, and phones are already set to one of them. The Filipino text, including the pest names *atangya* and *puting aksip*, is a draft that needs review by a native speaker before use outside the workshop (README; open task T073). The desktop app adds a language setting ([003-desktop-app research R6](../003-desktop-app/research.md)).
