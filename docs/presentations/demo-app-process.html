About this slide

This case study follows how one person directed an AI coding agent to plan, build, test and document an on-device rice-pest counter for Android over two days, 15–16 Oct 2026, and how it was extended on 17–18 Oct to download, switch and compare three published models. The app uses Flutter and ONNX Runtime; it began with an RT-DETR-r18vd model and now defaults to r50-v5 (RT-DETR-r50vd), with RF-DETR-M and D-FINE-L as alternatives. The app was first briefed as a tool for farmers; the project has since been scoped as a teaching demonstration, so the app is not made for farmers, is not official and has not been validated in the field.

Lesson · don't guess, read the source

Byte-exact on every shape but one

Symptom

One pixel in a 3×1200 test image was off by one level.

Investigation

A first guess at Pillow's rule was wrong on 26 probed shapes. Reading Pillow 12.3's C source settled it: only inputs under ~10 px wide differ.

Decision

No camera takes a 3-pixel-wide photo, so the app rejects photos under 32 px instead of chasing the edge case.

Result: byte-identical on all 8 fixture shapes, from 37×23 up to 4032×3024.

Demo app process12

About this slide

One check failed: in a 3×1200 test image, a single pixel was off by one level. A first guess at Pillow’s resize rule was wrong on 26 probed shapes. Reading the C source of Pillow 12.3 settled it: only inputs under about 10 pixels wide differ, because Pillow orders its resize passes differently for them. No camera takes a 3-pixel-wide photo, so the decision was to reject photos under 32 pixels rather than chase the edge case. The result: byte-identical output on all 8 fixture shapes, from 37×23 up to 4032×3024. When a guess fails, read the source, then make a deliberate scope call.

Presenting

Ask: was rejecting tiny photos a shortcut? Answer: no; it is a recorded scope decision with a reason. Pitfall: do not present guessing as the method. Reading the source is what ended the search.

A test against Pillow found that the Dart image package already applies a JPEG’s EXIF rotation and then clears the tag. The inference contract would have rotated the photo a second time. The owner asked whether real weights could run in the demo app, with photos preloaded from the dataset. Checking first exposed the problem: the highest score the model gave any of 253 validation photos was 0.25. In 60 of 60 epochs, validation count accuracy stayed at the do-nothing baseline of 0.474, the score of a model that predicts nothing. Yet test species mAP50 was 0.835: the model ranks insects well, it just is not confident. The diagnosis was a calibration problem (scores that do not reflect how likely a detection is to be right), not a bad checkpoint. That is why nothing passed the 0.5 threshold.

Presenting

Ask: how can a model rank well yet count nothing? Answer: ranking depends on the order of scores; counting needs scores above a cut-off. Pitfall: do not call the model good without this caveat.

Every claim in the deck has a test behind it: 142 Python tests (data, metrics, training loop, notebook build, fixtures, export, parity, threshold, calibration), 140 Dart tests on the PC (contract, decoding, counting, history, model store and registry, import and download checks, strings, and screens including settings and compare) and 1 device test, which checks the real app starting with no model installed.
