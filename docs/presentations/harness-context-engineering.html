The puzzle from the SDD comparison

Move a framework to another agent: the files work, the gates may not

Artefacts are inputs to the model, and every harness can read a file. Gates, waves and auto-activation are calls into the harness, and no standard covers them.

Harnesses & context engineering02

About this slide

When you move an SDD framework to a different coding agent, two kinds of thing move with it. Markdown artefacts (spec.md, plan.md, tasks.md, skills, AGENTS.md) are inputs to the model, and every harness (the software around the model, defined on the next slide) can hand a file to the model, so they always work. Behaviour (gates that stop work, hooks, sub-agent waves, skill auto-activation, the bootstrap) is a call into the harness. Depending on the harness it runs as designed, runs partly under other names or becomes a sentence in a prompt that the model may ignore. No standard covers these calls.

Harnesses & context engineering03

About this slide

The working definition is Agent = Model + Harness. In LangChain’s words, the harness is every piece of code, configuration and execution logic that is not the model itself: the loop, tools, permissions and hooks. Philipp Schmid’s analogy helps: the model is the CPU that reasons and picks actions, the context window is RAM (limited and volatile), the harness is the operating system and the agent is the application you run. Anthropic and OpenAI use the word for their own products; Google ships the same functions without it. The term has no formal definition yet, and a June 2026 preprint (arXiv 2606.10106) notes it is applied inconsistently.

Presenting

About this slide

Four layers sit between the model and your spec. The model (Claude, GPT, Gemini) and the vendor runtime harness (Claude Code, Codex, Copilot, Cursor, Antigravity, Kiro) belong to vendors. SDD frameworks are packaged project-level harnesses. They never own the loop; they call the runtime’s extension points as an app calls an operating system. The vendor draws the line itself

Instruction files are context, not enforcement

Instruction files are "context, not enforced configuration. To block an action regardless of what Claude decides, use a PreToolUse hook instead."

— Claude Code memory docs

Prompt rule

"Don't plan until the spec is approved." The model decides whether to follow it. Travels to any harness as text.

Hook

A PreToolUse deny blocks the tool even in bypass-permissions mode; a Stop hook can require passing tests. Works only where that event exists.

Compaction erases prose

Early instructions "can get lost". Fix: re-inject with a SessionStart hook after compaction. Superpowers on Hermes (no such hook) "loses the bootstrap".

Böckeler's terms: computational controls are deterministic, cheap, run on every change; inferential controls are slower and "more non-deterministic".

Harnesses & context engineering08

About this slide

Claude Code’s own documentation draws the line: instruction files are “context, not enforced configuration”, and to block an action regardless of what the model decides you use a PreToolUse hook. A prompt rule such as “do not plan until the spec is approved” travels to any harness as text, but the model decides whether to follow it. A hook is code the harness runs: a PreToolUse deny blocks a tool even in bypass-permissions mode, and a Stop hook can require passing tests, but only where that event exists. Compaction can also drop early instructions; the fix is to re-inject them with a SessionStart hook. Superpowers on Hermes, which has no such hook, “loses the bootstrap”.

A scale for classifying any framework's gates

Six tiers of gate strength

Design rule: back the gates that matter with tier 5. Treat tier-4 hooks as harness-specific accelerators that catch problems earlier, not as the guarantee.

Harnesses & context engineering09

About this slide

A six-tier scale for any framework’s gates. Tier 1 is instruction text: the model decides, and it travels as text. Tier 2 is format and structure (a JSON task list, checklists): still the model’s choice, with less drift. Tier 3 is an LLM judge that the harness triggers: probabilistic and rarely portable, since Codex skips such hooks. Tier 4 is a harness hook or product feature: deterministic, but per harness and often renamed. Tier 5 is external tests, linters and CI (continuous integration, checks that run on every change): deterministic and fully harness-independent. H is human approval, which travels if someone reads the artefact. Design rule: back the gates that matter with tier 5.

Presenting

Walk the tiers from weakest to strongest. Ask the room to place one rule they rely on today on the scale. Pitfall: do not present tier-4 hooks as the guarantee; the slide treats them as accelerators that catch problems earlier.

LangChain's taxonomy

Four moves cover the technique space

Harness functions (frameworks can't change them): caching, compaction, tool-result clearing, skill loading, sub-agent spawning. Workflow choices (frameworks package them): instruction files, which skills exist, state files, when to start fresh.

Harnesses & context engineering13

About this slide

LangChain sorts the techniques into four moves. Write keeps state outside the window in scratchpads, memories and files (in SDD: spec.md, STATE.md, plans). Select loads only what this step needs: a skill costs about 100 tokens of metadata at start, and its full SKILL.md (under 5k tokens) loads only when used. Compress shrinks history by trimming, summarising and compaction. Isolate splits work across separate windows: sub-agents return condensed 1,000–2,000-token summaries, but multi-agent work can use up to 15× the tokens of chat. Some of these are harness functions a framework cannot change (caching, compaction, skill loading, sub-agent spawning); others are workflow choices frameworks package (instruction files, state files, when to start fresh).

Standards

Files and protocols are standardised; hooks and orchestration are not

Result: every framework ships a per-harness installer. Spec Kit maps 35+ agents to different directories and keeps a public list of per-agent workarounds. The only hook-standard proposal found is one person's three-commit draft.

Harnesses & context engineering19

About this slide

Standards exist for files and protocols, but each stops short of where SDD behaviour lives. AGENTS.md fixes a file name and location, not when it loads or how much weight it gets. Agent Skills fixes the folder, frontmatter and disclosure stages, but leaves activation to each client, which is why auto-activation does not travel. MCP (agent to tool), ACP (editor to agent) and A2A (agent to remote agent) are wire protocols. Plugin marketplaces are per vendor. Lifecycle hooks and sub-agent orchestration have no standard; hooks share only a de facto shape (JSON in and out, exit 2 blocks). So every framework ships a per-harness installer; Spec Kit maps 35+ agents to different directories.

A conflict worth teaching

Do AGENTS.md files help? Two studies, two answers

ETH Zurich + LogicStar · arXiv 2602.11988

Success on hard, niche tasks

  • 4 agent–model pairs; SWE-bench Lite + 138 new tasks
  • LLM-generated files: success −0.5 to −2 pts, cost +20–23%
  • Minimal human-written files: +4 pts (not for Claude Code)
  • Agents followed the files; extra rules meant more exploring and testing

Lulla et al. · arXiv 2601.20404

Efficiency on ordinary PRs

  • 124 pull requests across 10 repositories, with vs without
  • Median runtime −28.6%
  • Output tokens −16.6%
  • "Comparable task completion behavior"

Defensible reading: short, hand-written files that state what the agent can't discover itself help modestly; large generated files cost money without improving success. Both studies are small, Python-heavy and lack significance tests.

Tier every gate

Gates that matter → tier 5

Skills as the portable unit

Small, hand-written context

Non-negotiable rules first, everything else in on-demand skills. GSD's byte ceilings are a model.

Pick the harness first

About this slide

The closing reframe. A spec is a context-engineering artefact: a curated, durable, high-signal set of tokens that lets a fresh context pick up the work, and any harness can read it. A gate is a harness-engineering artefact: it runs somewhere, so ask where a framework’s enforcement runs and whether that place exists on the harness your team will actually use. Tests and CI are the only gates that are both deterministic and portable. Teach SDD as practices (small context, phase-sized work, state on disk, gates as tests), with any framework as one implementation. The frameworks themselves are compared in Module 3 of coding-with-ai-agents-2h.html, in the same folder.
